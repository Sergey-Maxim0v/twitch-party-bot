# Ручное тестирование Twitch Party Bot

Документ содержит полный перечень ручных проверок всех фич приложения.
Каждый пункт оформлен как чекбокс-тест с описанием действий и ожидаемого результата.

---

## Как пользоваться документом

### Формат записи

```
- [ ] Номер. Название проверки
  - Действие: что именно нужно сделать.
  - Ожидаемый результат: что должно произойти.
```

* Отмечайте чекбокс `- [x]`, если проверка пройдена.
* Если проверка не пройдена — записывайте фактический результат рядом с пунктом.
* Пункты с пометкой **(авто)** можно выполнить в любой момент — они не требуют стрима.

### Подготовка окружения

| Что | Зачем |
| --- | --- |
| Приложение на `http://localhost:5173/` (`npm run dev`) или на GitHub Pages | Основной стенд |
| Аккаунт **стримера** (владелец канала) | Авторизация, модераторские права, собственный канал |
| Аккаунт **модератора** на канале стримера | Проверка модераторских команд `!add`, `!delete`, `!clear` и т.д. |
| Аккаунт **обычного зрителя** (не подписчик) | Проверка команд зрителей и ограничений |
| Аккаунт **подписчик / VIP** канала | Проверка приоритета и режима «только для подписчиков» |
| Второй браузер / вкладка | Проверка синхронизации между вкладками |
| DevTools → Console + Application | Проверка `sessionStorage`, `localStorage`, ошибок |

### Полезные ключи хранилища

| Ключ | Хранилище | Что хранит |
| --- | --- | --- |
| `tqp_twitch_session_v2` | sessionStorage | Токен и профиль Twitch-сессии (живёт только во вкладке) |
| `tqp_active_channel` | localStorage | Выбранный канал (переживает перезагрузку, общий для вкладок) |
| `twitch_queue_status` | localStorage | Флаг «очередь открыта/закрыта» |
| `twitch_queue_data` | localStorage | Активная очередь, ожидающие, история, кулдауны |
| `twitch_queue_settings` | localStorage | Все настройки очереди, бан-лист, выбранная игра |
| `twitch_party_theme` | localStorage | Выбранная тема (`nord` / `dim` / `system`) |
| `panel_settings_open`, `panel_queue_open`, `panel_logs_open`, `panel_chat_open` | localStorage | Состояние панелей |

> **Важно:** токен хранится в `sessionStorage` — закрытие вкладки завершает сессию. Выбранный канал и настройки очереди хранятся в `localStorage` — они сохраняются.

## 1. Авторизация через Twitch

### 1.1. Экран приветствия (до авторизации)

- [ ] **1.1.1. Отображение экрана приветствия**
  - **Действие:** Откройте приложение в браузере, где нет активной сессии (очистите `sessionStorage`).
  - **Ожидаемый результат:** Показан экран с логотипом Twitch, заголовком `Twitch Party Queue`, описанием «Собирайте зрителей в пати для совместных игр прямо во время стрима…» и кнопкой `Авторизоваться через Twitch`. Панели `Настройки`, `Очередь`, `Логи`, `Чат трансляции` не отображаются.

- [ ] **1.1.2. Кнопка «Войти» в шапке**
  - **Действие:** На неавторизованном экране посмотрите на правый угол шапки.
  - **Ожидаемый результат:** Кнопка `Войти` с иконкой Twitch и переключатель темы. Панели рабочего пространства скрыты.

### 1.2. Успешная авторизация

- [ ] **1.2.1. Вход через всплывающее окно**
  - **Действие:** Нажмите `Авторизоваться через Twitch` (или `Войти` в шапке).
  - **Ожидаемый результат:** Открылось всплывающее окно Twitch (500×650). В приложении показано модальное окно со спиннером, заголовком `Авторизация на Twitch` и текстом `Пожалуйста, завершите вход в открывшемся всплывающем окне.` Есть кнопки `Отмена` и `Войти в текущей вкладке`.

- [ ] **1.2.2. Стадия «Проверка токена»**
  - **Действие:** Авторизуйтесь в окне Twitch и разрешите доступ.
  - **Ожидаемый результат:** Модальное окно переходит на стадию `Проверка токена` со спиннером и текстом `Верифицируем вашу сессию через официальный API Twitch...`. Кнопок на этой стадии нет.

- [ ] **1.2.3. Стадия «Успешный вход»**
  - **Действие:** Дождитесь ответа Twitch API.
  - **Ожидаемый результат:** Показан зелёный значок, заголовок `Успешный вход!` и текст `Добро пожаловать. Окно сейчас закроется автоматически.` Через ~1 секунду модальное окно закрывается, всплывающее окно Twitch закрывается.

- [ ] **1.2.4. Открытие рабочего пространства**
  - **Действие:** После успешного входа осмотрите интерфейс.
  - **Ожидаемый результат:** Отображаются 4 панели: `Настройки`, `Очередь`, `Логи`, `Чат трансляции`. В шапке — индикаторы `Сеть` и `Чат`, а также выпадающее меню профиля со строками `канал:` и `аккаунт:`.

- [ ] **1.2.5. Запись в журнал приложений**
  - **Действие:** Откройте панель `Логи`.
  - **Ожидаемый результат:** Есть запись вида `Вы вошли в аккаунт: <Отображаемое имя>` (зелёный/успешный статус), источник — `Система`.

### 1.3. Альтернативный вход (fallback)

- [ ] **1.3.1. Вход в текущей вкладке (из стадии ожидания)**
  - **Действие:** Нажмите `Авторизоваться через Twitch`, затем в модальном окне нажмите `Войти в текущей вкладке`.
  - **Ожидаемый результат:** Текущая вкладка переходит на страницу авторизации Twitch (полная перезагрузка). После успешного входа приложение открывается заново, сессия активна.

- [ ] **1.3.2. Очистка URL после возврата**
  - **Действие:** В адресной строке после возврата из OAuth посмотрите на параметры.
  - **Ожидаемый результат:** Параметры `#access_token=...` и `#state=...` удалены из адресной строки (используется `history.replaceState`), токен не остаётся в истории браузера.

- [ ] **1.3.3. Блокировка всплывающих окон**
  - **Действие:** Заблокируйте всплывающие окна для сайта в настройках браузера, затем нажмите `Авторизоваться через Twitch`.
  - **Ожидаемый результат:** Модальное окно переходит в стадию `Ошибка входа` с текстом `Всплывающее окно заблокировано браузером. Войдите в текущей вкладке.` Доступны кнопки `Повторить`, `Закрыть` и `Войти в текущей вкладке`.

- [ ] **1.3.4. Отмена авторизации (закрытие окна вручную)**
  - **Действие:** Нажмите `Авторизоваться через Twitch`, затем закройте всплывающее окно Twitch, не авторизуясь.
  - **Ожидаемый результат:** В приложении появляется ошибка `Авторизация отменена: всплывающее окно было закрыто.` Можно нажать `Повторить` или `Войти в текущей вкладке`.

- [ ] **1.3.5. Кнопка «Отмена»**
  - **Действие:** Нажмите `Авторизоваться через Twitch`, затем в модальном окне нажмите `Отмена`.
  - **Ожидаемый результат:** Модальное окно и всплывающее окно Twitch закрываются. Пользователь остаётся на экране приветствия, ошибка не показывается.

- [ ] **1.3.6. Тайм-аут ожидания (5 минут)**
  - **Действие:** Запустите вход, оставьте всплывающее окно открытым без действий более чем на 5 минут (для ускорения — временно изменить таймер в коде).
  - **Ожидаемый результат:** Ошибка `Авторизация не завершена вовремя. Попробуйте снова.`

### 1.4. Ошибки авторизации

- [ ] **1.4.1. Отказ пользователя на стороне Twitch**
  - **Действие:** В окне Twitch нажмите «Отказать в доступе».
  - **Ожидаемый результат:** Стадия `Ошибка входа`, текст вида `Авторизация отклонена Twitch: <описание ошибки>`.

- [ ] **1.4.2. Ошибка CSRF (несовпадение `state`)**
  - **Действие:** Очистите ключ `twitch_oauth_state` в `sessionStorage` во время ожидания ответа OAuth.
  - **Ожидаемый результат:** Ошибка `Ошибка безопасности (CSRF): верификация контекста не пройдена.`

- [ ] **1.4.3. CSRF в popup при подмене `state`**
  - **Действие:** При обычном доступном хранилище откройте popup входа и подмените значение `state` в сообщении popup → родительское окно (или в URL возврата).
  - **Ожидаемый результат:** Вход не выполняется, показывается ошибка `Ошибка безопасности (CSRF): верификация контекста не пройдена.`

- [ ] **1.4.3. Недоступность Twitch API при проверке токена**
  - **Действие:** Включите офлайн-режим браузера перед завершением входа.
  - **Ожидаемый результат:** Ошибка `Не удалось проверить токен: Twitch недоступен. Проверьте соединение и попробуйте снова.`

- [ ] **1.4.4. Недействительный токен**
  - **Действие:** Подставьте в `sessionStorage` заведомо невалидный токен в ключ `tqp_twitch_session_v2` и перезагрузите страницу.
  - **Ожидаемый результат:** Приложение выходит из аккаунта и показывает экран приветствия.

- [ ] **1.4.5. Повреждённая сессия в хранилище**
  - **Действие:** Запишите в `tqp_twitch_session_v2` объект без `accessToken` и перезагрузите страницу.
  - **Ожидаемый результат:** В консоли — `Повреждённая сессия Twitch удалена из хранилища.` Запись удаляется, приложение считает пользователь неавторизованным.

- [ ] **1.4.6. Отсутствие Client ID в конфигурации**
  - **Действие:** Соберите приложение без переменной `VITE_TWITCH_CLIENT_ID` (или со значением `undefined`).
  - **Ожидаемый результат:** Ошибка `Twitch Client ID не найден в конфигурации приложения. Проверьте настройки CI/CD.`

### 1.5. Выход из аккаунта

- [ ] **1.5.1. Выход через меню профиля**
  - **Действие:** Откройте выпадающее меню в шапке, нажмите на строку `аккаунт:` (или бейдж `Выйти`).
  - **Ожидаемый результат:** Сессия удаляется из `sessionStorage`, отображается экран приветствия, в шапке снова кнопка `Войти`. Подтверждения в виде диалога **нет** — выход происходит сразу.

- [ ] **1.5.2. Канал сохраняется после выхода**
  - **Действие:** После выхода посмотрите значение `tqp_active_channel` в `localStorage`.
  - **Ожидаемый результат:** Выбранный канал **не** очищается. При следующем входе модальное окно выбора канала автоматически не открывается — нужно нажать `Сменить`.

### 1.6. Недоступное хранилище

- [ ] **1.6.1. Загрузка при заблокированном Web Storage**
  - **Действие:** Откройте приложение в окружении, где доступ к хранилищу запрещён: iframe с `sandbox="allow-scripts"` без `allow-same-origin` или Firefox с `dom.storage.enabled=false`.
  - **Ожидаемый результат:** Приложение отображается (экран приветствия), белого экрана нет, ошибок рендера в консоли нет. Под кнопкой входа показано предупреждение `Браузер ограничивает хранилище: часть данных и настроек не сохранится после перезагрузки.` Ошибки доступа к Web Storage выводятся в консоль не чаще одного раза на операцию и ключ, без повторения при каждой записи.

- [ ] **1.6.2. Вход через popup при заблокированном Web Storage**
  - **Действие:** В окружении из п. 1.6.1 (например, Firefox с `dom.storage.enabled=false`) нажмите `Авторизоваться через Twitch` и завершите вход во всплывающем окне.
  - **Ожидаемый результат:** Popup открывается, после возврата из Twitch приложение авторизуется: `state` проверяется в возвращённом окне через `sessionStorage`. При недоступном хранилище сессия работает в памяти до перезагрузки, в модалке успеха показано предупреждение о том, что часть данных не сохранится.

- [ ] **1.6.3. Вход в текущей вкладке при заблокированном Web Storage**
  - **Действие:** В окружении из п. 1.6.1 откройте модальное окно авторизации и проверьте доступные способы входа.
  - **Ожидаемый результат:** Кнопка `Войти в текущей вкладке` скрыта, вместо неё показан текст `Вход в текущей вкладке недоступен: браузер блокирует хранилище...`. Если вызвать действие программно, навигация на Twitch не начинается и показывается та же ошибка.

- [ ] **1.6.4. Возврат из OAuth при недоступном хранилище**
  - **Действие:** Откройте приложение с параметрами `#access_token=test&state=test` в окружении из п. 1.6.1.
  - **Ожидаемый результат:** Спиннер загрузки завершается, OAuth-параметры удаляются из адресной строки, показывается ошибка `Браузер блокирует хранилище, поэтому не удалось проверить состояние авторизации...`. Сырой `SecurityError`/`DOMException` в интерфейсе не появляется.

## 2. Выбор канала

### 2.1. Модальное окно выбора канала

- [ ] **2.1.1. Автооткрытие после первого входа**
  - **Действие:** Войдите в приложение, когда в `localStorage` нет ключа `tqp_active_channel` (или там `"null"`).
  - **Ожидаемый результат:** Сразу после успешного входа автоматически открывается модальное окно с заголовком `Выбор канала чата` и подзаголовком `Укажите канал, сообщения которого бот должен начать отслеживать.`

- [ ] **2.1.2. Содержимое модального окна**
  - **Действие:** Осмотрите открытое окно.
  - **Ожидаемый результат:** Присутствуют: карточка `Текущий канал`, кнопка `Подключить канал` с вашим отображаемым именем, поле ввода с плейсхолдером `Название канала` и кнопка подключения под полем.

- [ ] **2.1.3. Кнопка подключения в состоянии «пусто»**
  - **Действие:** Оставьте поле ввода пустым.
  - **Ожидаемый результат:** На кнопке крупно написано `Введите название`, кнопка **неактивна** (disabled).

- [ ] **2.1.4. Кнопка подключения с введённым значением**
  - **Действие:** Введите в поле `mychannel`.
  - **Ожидаемый результат:** Кнопка активна; на ней мелким шрифтом `Подключить канал` и крупно — введённое значение. Кнопка неактивна во время проверки канала (показывается спиннер).

- [ ] **2.1.5. Закрытие модального окна**
  - **Действие:** Когда канал уже выбран, нажмите крестик в правом верхнем углу или `Escape`, либо кликните по затемнённому фону.
  - **Ожидаемый результат:** Окно закрывается. При первом выборе канала (когда в системе ещё нет канала) крестик и `Escape` **не работают**, фон не закрывает окно — выбрать канал обязательно.

- [ ] **2.1.6. Повреждённое значение выбранного канала**
  - **Действие:** Запишите в `tqp_active_channel` заведомо некорректный JSON (например, `{`) и перезагрузите страницу.
  - **Ожидаемый результат:** Приложение открывается, модальное окно выбора канала показывается автоматически, как при отсутствии канала. Белого экрана нет, в консоли — сообщение об ошибке чтения `localStorage`.

### 2.2. Выбор своего канала

- [ ] **2.2.1. Подключение своего канала**
  - **Действие:** В модальном окне нажмите кнопку `Подключить канал` с вашим отображаемым именем.
  - **Ожидаемый результат:** Канал выбирается и подключается, модальное окно закрывается автоматически. В шапке в строке `канал:` отображается имя вашего канала.

- [ ] **2.2.2. Ошибка «Канал не найден» для своего канала**
  - **Действие:** Войдите под аккаунтом, у которого нет публичного канала, и нажмите кнопку подключения своего канала.
  - **Ожидаемый результат:** Ошибка `Канал не найден на Twitch.`

### 2.3. Выбор произвольного канала

- [ ] **2.3.1. Успешное подключение к чужому каналу**
  - **Действие:** Введите в поле `Название канала` существующий канал (например, `twitch` или свой тестовый канал) и нажмите кнопку подключения.
  - **Ожидаемый результат:** Канал выбирается, модальное окно закрывается, чат начинает принимать сообщения, в карточке `Текущий канал` появляется статус `Подключен`.

- [ ] **2.3.2. Регистр и пробелы**
  - **Действие:** Введите ` MyChannel ` (с пробелами и заглавными буквами) и подключитесь.
  - **Ожидаемый результат:** Подключение проходит. В кнопке отображается «сырое» значение с пробелами, но сохранённый канал — обрезанный и в нижнем регистре (`mychannel`). В шапке видно нормализованное имя.

- [ ] **2.3.3. Несуществующий канал**
  - **Действие:** Введите заведомо несуществующий канал (например, `zzz_nonexistent_channel_999`) и подключитесь.
  - **Ожидаемый результат:** Ошибка `Канал не найден на Twitch.` Поле ввода подсвечивается красным (`input-error`), текст ошибки выводится под полем.

- [ ] **2.3.4. Некорректное имя канала**
  - **Действие:** Введите `a` (1 символ), `ab-cd` (дефис), `ab cd` (пробел), `канал` (кириллица) или 26+ символов.
  - **Ожидаемый результат:** Ошибка `Некорректное имя канала Twitch.` Проверка: допустимы только `a-z`, `0-9`, `_`, длина 2–25 символов (регистр и внешние пробелы игнорируются).

- [ ] **2.3.5. Сброс ошибки при вводе**
  - **Действие:** После появления ошибки начните печатать в поле.
  - **Ожидаемый результат:** Сообщение `Канал не найден на Twitch.` исчезает, поле возвращается в обычное состояние.

### 2.4. Смена канала

- [ ] **2.4.1. Кнопка «Сменить»**
  - **Действие:** Откройте меню профиля в шапке, нажмите строку `канал:` с бейджем `Сменить`.
  - **Ожидаемый результат:** Открывается модальное окно выбора канала с текущим каналом в карточке `Текущий канал`.

- [ ] **2.4.2. Очистка чата при смене канала**
  - **Действие:** Подключитесь к новому каналу, дождитесь сообщений в чате, затем переключитесь на другой канал.
  - **Ожидаемый результат:** История сообщений чата и логи чата очищаются, в чате появляются сообщения нового канала.

- [ ] **2.4.3. Лог смены канала**
  - **Действие:** Посмотрите панель `Логи` после переключения канала.
  - **Ожидаемый результат:** Есть записи `Подключение к каналу @<канал>...` и `Подключение к каналу @<канал> установлено.`

## 3. Информация о канале

- [ ] **3.1. Статус подключения канала**
  - **Действие:** Откройте модальное окно выбора канала.
  - **Ожидаемый результат:** В карточке `Текущий канал` справа бейдж `Подключен` (зелёный) при успешном подключении либо `Не подключен` (серый).

- [ ] **3.2. Подсказка при отсутствии подключения**
  - **Действие:** Отключитесь от сети и откройте карточку.
  - **Ожидаемый результат:** Показан текст `Канал не подключён. Подключите канал, чтобы увидеть роли и ограничения чата.`

- [ ] **3.3. Определение ролей**
  - **Действие:** Подключитесь к каналу и дождитесь определения ролей (обычно мгновенно для своего канала).
  - **Ожидаемый результат:** В секции `Роли` отображаются бейджи по ролям: `Broadcaster`, `Модератор`, `VIP`, `Подписчик`. Если ни одна роль не применима — бейдж `Гость`. Пока данные не получены — текст `Определяются…`.

- [ ] **3.4. Ограничения чата**
  - **Действие:** Включите на канале режим «только подписчики» / «только смайлы» / «только фолловеры» / медленный режим / уникальные сообщения и посмотрите карточку.
  - **Ожидаемый результат:** В секции `Ограничения чата` появляются бейджи: `Только подписчики`, `Только смайлы`, `Только фолловеры`, `Медленный режим`, `Уникальные сообщения`. Если ограничений нет — бейдж `Без ограничений`. У каждого бейджа есть тултип с описанием (например, `только для подписчиков`, `медленный режим (30 сек.)`).

## 4. Подключение и статус сети

- [ ] **4.1. Индикаторы в шапке**
  - **Действие:** Посмотрите на индикаторы `Сеть` и `Чат` в шапке.
  - **Ожидаемый результат:** Присутствуют два чипа. У каждого — текстовый статус и цветная точка. При наведении (на экранах ≥ lg) появляется тултип с подробным описанием.

- [ ] **4.2. Статусы сети**
  - **Действие:** Отследите переходы подключения.
  - **Ожидаемый результат:** Возможные статусы: `Подключен` (зелёный, пульсирует), `Ожидание` (жёлтый, пульсирует), `Ошибка` (красный), `Отключен` (красный). Тултипы: «Стабильное WebSocket-соединение с сервером Twitch IRC установлено. Ошибок нет.», «Выполняется подключение к серверам Twitch... Пожалуйста, подождите.», «Подключение к Twitch не восстановлено. Причина указана в журнале приложения.», «Соединение с сервером отсутствует. Проверьте интернет или статус авторизации.»

- [ ] **4.3. Статусы доступа к чату**
  - **Действие:** Наблюдайте индикатор `Чат`.
  - **Ожидаемый результат:** Возможные статусы: `Подключен` (полный доступ), `Ограничен` (можно читать, отправка заблокирована), `Забанен` (доступ заблокирован), `Не подключен` (инициализация не выполнена).

- [ ] **4.4. Обрыв сети и автопереподключение**
  - **Действие:** Выключите интернет на 10–20 секунд, затем включите обратно.
  - **Ожидаемый результат:** Индикатор `Сеть` переходит в `Отключен`/`Ошибка`, в логах появляется `Соединение с Twitch потеряно. Запуск автоматического восстановления...`. После возврата сети соединение восстанавливается автоматически, статус снова `Подключен`.

- [ ] **4.5. Автопереподключение с нарастающей задержкой**
  - **Действие:** Обесточьте сеть на длительное время (за пределами 5 попыток).
  - **Ожидаемый результат:** В логах появляются записи `Повторная попытка подключения к каналу @<канал> (№N)...` с нарастающими интервалами (≈2 с, 4 с, 8 с, 16 с, 30 с). После 5-й попытки — `Превышен лимит попыток подключения (5). Автоматическое восстановление остановлено.`

- [ ] **4.6. Кнопка «Переподключить»**
  - **Действие:** Доведите соединение до состояния превышения лимита попыток.
  - **Ожидаемый результат:** В шапке появляется красная кнопка `Переподключить`. Нажатие сбрасывает счётчик попыток и переподключает сокет.

- [ ] **4.7. Отказ Twitch в авторизации IRC**
  - **Действие:** Используйте заведомо невалидный/просроченный токен.
  - **Ожидаемый результат:** В логах `Twitch отклонил авторизацию: токен недействителен. Требуется повторный вход.` Приложение автоматически выходит из аккаунта и показывает экран приветствия. Кнопка `Переподключить` **не** появляется.

- [ ] **4.8. Heartbeat (PING/PONG)**
  - **Действие:** Оставьте приложение открытым на 10+ минут без действий (вкладка не в фокусе).
  - **Ожидаемый результат:** Соединение остаётся активным, статус `Подключен`, в логах нет ошибок. Таймер PING работает в фоновом Web Worker и не блокируется браузером.
  - **Проверка «полуоткрытого» соединения:** В DevTools подмените `WebSocket.prototype.send`, чтобы отбрасывать исходящие `PING`, и прекратите активность в чате. Ожидаемый результат: примерно через 60 секунд тишины бот отправит `PING`, а ещё через 10 секунд без `PONG` сокет будет принудительно пересоздан (статус сменится на `Ожидание`, затем вернётся `Подключен`). Входящие сообщения, пришедшие в эти 10 секунд, не должны отменять переподключение.

- [ ] **4.9. Серверный запрос RECONNECT**
  - **Действие:** Дождитесь планового переподключения от Twitch (или имитируйте через консоль).
  - **Ожидаемый результат:** В чате появляется системное сообщение `Получен системный запрос RECONNECT от сервера Twitch. Запускается процесс планового переподключения.` Соединение переустанавливается автоматически.

- [ ] **4.10. Офлайн/онлайн события браузера**
  - **Действие:** Переключите системный режим «в самолёте» / выключите-включите Wi-Fi.
  - **Ожидаемый результат:** Сокет уничтожается при переходе в офлайн, статус чата становится `Не подключен`. При возврате в онлайн — немедленное переподключение.

- [ ] **4.11. Сброс таймера ограничений чата при размонтировании**
  - **Действие:** Получите тайм-аут в чате, затем выйдите из аккаунта до истечения тайм-аута и дождитесь момента его окончания.
  - **Ожидаемый результат:** В журнале нет записи `Время таймаута истекло.`, индикатор чата не переключается на `Подключен`: таймер сбрасывается вместе с размонтированием чата.

## 5. Чат трансляции

### 5.1. Отображение сообщений

- [ ] **5.1.1. Получение сообщений**
  - **Действие:** Отправьте несколько сообщений в чат Twitch со второго аккаунта.
  - **Ожидаемый результат:** Сообщения появляются в панели `Чат трансляции` с отметкой времени в формате `ЧЧ:ММ:СС`, ником автора и текстом. Новые сообщения появляются снизу, старые — сверху.

- [ ] **5.1.2. Пустое состояние**
  - **Действие:** Откройте панель чата до поступления сообщений.
  - **Ожидаемый результат:** По центру показано курсивное `Ожидание сообщений из чата...`

- [ ] **5.1.3. Свои сообщения**
  - **Действие:** Отправьте сообщение из поля ввода приложения.
  - **Ожидаемый результат:** Сообщение появляется в чате от вашего ника. Текст не дублируется (после подтверждения `USERSTATE`).

- [ ] **5.1.4. Ограничение истории**
  - **Действие:** Сгенерируйте более 300 сообщений в чате.
  - **Ожидаемый результат:** В панели хранится не более 300 сообщений, самые старые постепенно исчезают.

- [ ] **5.1.5. Очистка истории при смене канала**
  - **Действие:** Смените канал (см. 2.4.2).
  - **Ожидаемый результат:** Сообщения предыдущего канала удаляются.

### 5.2. Ввод и отправка сообщений

- [ ] **5.2.1. Отправка по кнопке**
  - **Действие:** Введите текст в поле с плейсхолдером `Отправить сообщение` и нажмите кнопку `Отправить`.
  - **Ожидаемый результат:** Сообщение отправляется в чат Twitch и появляется в панели чата. Поле ввода очищается.

- [ ] **5.2.2. Отправка по Enter**
  - **Действие:** Введите текст и нажмите `Enter`.
  - **Ожидаемый результат:** Сообщение отправляется.

- [ ] **5.2.3. Перенос строки по Shift+Enter**
  - **Действие:** Введите текст, нажмите `Shift+Enter`.
  - **Ожидаемый результат:** Добавляется перенос строки, сообщение **не** отправляется.

- [ ] **5.2.4. Кнопка отправки при пустом поле**
  - **Действие:** Оставьте поле пустым (или введите только пробелы).
  - **Ожидаемый результат:** Кнопка `Отправить` неактивна (disabled).

- [ ] **5.2.5. Ограничение длины**
  - **Действие:** Вставьте текст длиннее 500 символов.
  - **Ожидаемый результат:** Ввод ограничен 500 символами (дополнительные символы не вводятся).

- [ ] **5.2.6. Автоувеличение поля**
  - **Действие:** Введите несколько строк текста.
  - **Ожидаемый результат:** Высота поля растёт вместе с содержимым (до появления внутренней прокрутки).

- [ ] **5.2.7. Ошибка отправки**
  - **Действие:** Отключите интернет и попробуйте отправить сообщение.
  - **Ожидаемый результат:** Сообщение **не теряется** — текст остаётся в поле. В логах появляется запись `Не удалось отправить сообщение в чат: <причина>.`

- [ ] **5.2.8. Цвет кнопки отправки**
  - **Действие:** Наблюдайте кнопку `Отправить` в разных состояниях доступа к чату.
  - **Ожидаемый результат:** Цвет кнопки соответствует статусу чата: синий (полный доступ), жёлтый (ограничен), красный (нет доступа), серый (забанен).

### 5.3. Настройки отображения чата

> Все переключатели находятся в выпадающей панели `Отображение чата` (иконка шестерёнки `Настройки чата` рядом с полем ввода).

- [ ] **5.3.1. «Цветные ники»**
  - **Действие:** Включите тумблер `Цветные ники`.
  - **Ожидаемый результат:** Ники с цветовым стилем Twitch отображаются в соответствующем цвете (цвет адаптируется под светлую/тёмную тему). При выключении — стандартный цвет ника.

- [ ] **5.3.2. «Стили модеров, випов»**
  - **Действие:** Включите тумблер `Стили модеров, випов` и дождитесь сообщений от модератора, VIP и стримера.
  - **Ожидаемый результат:** Сообщения стримера подсвечиваются красным фоном с иконкой Twitch, модератора — зелёным с иконкой меча, VIP — голубым с иконкой гема.

- [ ] **5.3.3. «Выделенные сообщения»**
  - **Действие:** Включите тумблер `Выделенные сообщения` и отправьте «выделенное» сообщение (highlighted message) в чате.
  - **Ожидаемый результат:** Такое сообщение обведено первичной рамкой (2 px).

- [ ] **5.3.4. «Показать удаленные сообщения»**
  - **Действие:** Выключите тумблер, затем удалите сообщение модератором в Twitch.
  - **Ожидаемый результат:** Удалённое сообщение **не отображается**. Включите тумблер — сообщение появляется с пониженной прозрачностью и иконкой предупреждения.

- [ ] **5.3.5. «Показать системные сообщения»**
  - **Действие:** Выключите тумблер и вызовите системное событие (например, очистку чата модератором).
  - **Ожидаемый результат:** Системные сообщения скрыты. При включении — отображаются с иконкой гаечного ключа: `Чат был очищен модератором.`

- [ ] **5.3.6. Открытие и закрытие выпадающих настроек**
  - **Действие:** Кликните по иконке шестерёнки, затем кликните вне панели.
  - **Ожидаемый результат:** Панель `Отображение чата` открывается на 5 переключателей и закрывается при клике вне. Панель открывается также при фокусе с клавиатуры (Tab).

### 5.4. Системные сообщения в чате

- [ ] **5.4.1. Очистка чата модератором**
  - **Действие:** Очистите чат в Twitch от имени модератора.
  - **Ожидаемый результат:** В чате появляется `Чат был очищен модератором.`

- [ ] **5.4.2. Бан пользователя**
  - **Действие:** Забаните пользователя в чате Twitch на 60 секунд.
  - **Ожидаемый результат:** `Пользователь @<ник> заблокирован на 60 сек.`

- [ ] **5.4.3. Перманентный бан**
  - **Действие:** Забаните пользователя навсегда.
  - **Ожидаемый результат:** `Пользователь @<ник> забанен навсегда.`

- [ ] **5.4.4. Удаление отдельного сообщения**
  - **Действие:** Удалите конкретное сообщение в Twitch.
  - **Ожидаемый результат:** `Сообщение от @<ник> удалено.`

- [ ] **5.4.5. Подписка**
  - **Действие:** Оформите тестовую подписку на канале.
  - **Ожидаемый результат:** `@<ник> оформляет подписку! Всего месяцев: N`

- [ ] **5.4.6. Режимы канала**
  - **Действие:** Включите и выключите режимы канала (только подписчики, только смайлы, только фолловеры, медленный, уникальные сообщения).
  - **Ожидаемый результат:** В чате появляются соответствующие сообщения, например `Включен режим "Только для подписчиков".` и `Режим "Только для подписчиков" отключен.` Дублирующие английские NOTICE не показываются.

- [ ] **5.4.7. Исходный пакет ROOMSTATE**
  - **Действие:** Подключитесь к каналу с включёнными ограничениями.
  - **Ожидаемый результат:** Первичный пакет `ROOMSTATE` **не** отображается в чате (в логах при этом может быть запись об активных ограничениях).

## 6. Очередь — управление

### 6.1. Открытие и закрытие очереди

- [ ] **6.1.1. Открытие очереди**
  - **Действие:** Нажмите кнопку `Открыть очередь` в панели `Очередь`.
  - **Ожидаемый результат:** Кнопка меняется на `Закрыть очередь` (красная обводка). В логах: `Открыта очередь, участники чата могут добавляться.` Зрители могут вступать командой `!join`.

- [ ] **6.1.2. Закрытие очереди**
  - **Действие:** Нажмите `Закрыть очередь`.
  - **Ожидаемый результат:** Кнопка меняется на `Открыть очередь`. В логах: `Закрыта очередь, добавлять в очередь могут только модераторы в чате и пользователь приложения.` Состав очереди **не** очищается. Зрители больше не могут вступить.

- [ ] **6.1.3. Повторное открытие/закрытие**
  - **Действие:** Нажмите `Открыть очередь`, когда очередь уже открыта (через `!start` от модератора).
  - **Ожидаемый результат:** В логах появляется предупреждение `Очередь уже открыта.` и состояние не меняется.

- [ ] **6.1.4. Автозакрытие при закрытии вкладки**
  - **Действие:** Откройте очередь, затем закройте вкладку или обновите страницу.
  - **Ожидаемый результат:** В логах `Очередь автоматически закрыта из-за перезагрузки страницы или закрытия вкладки приложения.` После перезагрузки очередь считается закрытой.

- [ ] **6.1.5. Автозакрытие при смене канала**
  - **Действие:** Откройте очередь и переключитесь на другой канал.
  - **Ожидаемый результат:** В логах `Очередь автоматически закрыта в связи с переключением на канала.` (в тексте есть грамматическая особенность — сверять с исходной строкой).

### 6.2. Списки очереди

- [ ] **6.2.1. Активная очередь**
  - **Действие:** Добавьте 2 игроков.
  - **Ожидаемый результат:** Секция `Текущая очередь` показывает бейдж `2 / 4` (2 из лимита 4). При лимите 0 отображается просто `2`.

- [ ] **6.2.2. Список ожидающих**
  - **Действие:** Включите настройку `Разрешить запись в список ожидающих` и добавьте больше игроков, чем вмещает лимит.
  - **Ожидаемый результат:** Секция `Список ожидающих` показывает бейдж `N / max` и список игроков. Список автоматически раскрывается.

- [ ] **6.2.3. Отключённый список ожидающих**
  - **Действие:** Выключите `Разрешить запись в список ожидающих`.
  - **Ожидаемый результат:** Блок `Список ожидающих` приглушён (opacity 70), при наведении показывается тултип `Список ожидающих отключен в настройках`, содержимое скрыто. Список ожидающих при этом **очищается** (в логах `Список ожидающих очищен.`).

- [ ] **6.2.4. История**
  - **Действие:** Завершите сессию очереди (см. 6.3) и посмотрите секцию `История`.
  - **Ожидаемый результат:** Появляется карточка состава с названием `Состав №1` и временем `Время: 12:34`. Бейдж секции показывает число сессий (без `/max`).

- [ ] **6.2.5. Пустой состав в истории**
  - **Действие:** Завершите пустую очередь через `!play` модератором.
  - **Ожидаемый результат:** В логах `Не удалось завершить сессию: Очередь пуста.` В истории карточка с текстом `Нет участников в составе`.

- [ ] **6.2.6. Ограничение истории**
  - **Действие:** Завершите более 100 сессий (или внесите значения напрямую в `twitch_queue_data`).
  - **Ожидаемый результат:** Хранится не более 100 последних сессий, более старые отбрасываются. Счётчик `globalSessionCounter` при этом не сбрасывается.

### 6.3. Завершение сессии

- [ ] **6.3.1. Завершение из интерфейса**
  - **Действие:** Нажмите `Завершить текущую очередь`.
  - **Ожидаемый результат:** Активная очередь очищается, состав попадает в `Историю` как `Состав №N`. В логах `Состав №N завершен (игроков: N).` Если очередь была открыта — `Очередь автоматически закрыта в связи с завершением сессии.` и кнопка снова `Открыть очередь`.

- [ ] **6.3.2. Автоперенос после завершения**
  - **Действие:** При заполненном списке ожидающих и включённом `Разрешить автоперенос игроков из списка ожидающих при изменении размера очереди` завершите сессию.
  - **Ожидаемый результат:** Игроки из списка ожидающих автоматически переносятся в активную очередь (в конец). В логах `Автоматически перенесено игроков из списка ожидающих в конец активной очереди: N.`

- [ ] **6.3.3. Кулдауны игроков**
  - **Действие:** Завершите сессию с игроком, затем попробуйте зайти снова.
  - **Ожидаемый результат:** В истории игрока фиксируются `lastPlayedTimestamp`, номер последней сессии и число сыгранных игр — это влияет на проверки лимита игр и кулдаунов (см. 7.2.7–7.2.9).

### 6.4. Ручное добавление игрока

- [ ] **6.4.1. Добавление из формы**
  - **Действие:** В панели `Очередь` введите ник в поле `Никнейм Twitch...` и нажмите `Добавить в очередь`.
  - **Ожидаемый результат:** Игрок появляется в активной очереди. Поля формы очищаются. В логах — запись об источнике `Пользователь приложения`.

- [ ] **6.4.2. Неактивная кнопка без ника**
  - **Действие:** Оставьте поле ника пустым.
  - **Ожидаемый результат:** Кнопка `Добавить в очередь` неактивна.

- [ ] **6.4.3. Роли при ручном добавлении**
  - **Действие:** Отметьте чекбоксы `Mod`, `Sub`, `VIP` и добавьте игрока.
  - **Ожидаемый результат:** В карточке игрока видны бейджи `Модер` (зелёный), `VIP` (жёлтый), `Саб` (голубой). Все чекбоксы сбрасываются после добавления.

- [ ] **6.4.4. Сообщение / игровой ник**
  - **Действие:** Введите текст в поле `Сообщение или игровой ник...` и добавьте игрока.
  - **Ожидаемый результат:** Текст отображается курсивом в карточке игрока; при выбранной игре в настройках из текста извлекается игровой ник (зелёный чип).

- [ ] **6.4.5. Дубликаты**
  - **Действие:** Добавьте одного и того же ника дважды (с разным регистром).
  - **Ожидаемый результат:** Второе добавление отклоняется с логом `Добавление в очередь: Отклонено, игрок <ник> уже в активной очереди, список ожидающих отключен.` (или соответствующий вариант для включённого списка ожидающих).

- [ ] **6.4.6. Ручное добавление в закрытую очередь**
  - **Действие:** Закройте очередь и добавьте игрока из формы.
  - **Ожидаемый результат:** Добавление проходит — ручное добавление доступно независимо от состояния очереди.

### 6.5. Карточка игрока

- [ ] **6.5.1. Содержимое карточки**
  - **Действие:** Посмотрите на карточку добавленного игрока.
  - **Ожидаемый результат:** Видны: иконка часов и время добавления (`ЧЧ:ММ:СС`), бейджи ролей (`Модер`, `VIP`, `Саб`), отображаемый ник, чип игрового ника (с иконкой геймпада) и курсивный исходный текст сообщения. При наведении на текст — полный текст в тултипе.

- [ ] **6.5.2. Копирование игрового ника**
  - **Действие:** Кликните по чипу с игровым ником.
  - **Ожидаемый результат:** Ник копируется в буфер обмена. Тултип чипа: `Кликните, чтобы скопировать ник`. Если нет игрового ника — копируется отображаемый ник.

- [ ] **6.5.3. Кнопка «Подробно»**
  - **Действие:** Нажмите `Подробно` на карточке.
  - **Ожидаемый результат:** Открывается модальное окно `Карта участника очереди` (см. 6.6).

- [ ] **6.5.4. Кнопка «Удалить»**
  - **Действие:** Нажмите `Удалить` на карточке игрока в активной очереди или в списке ожидающих.
  - **Ожидаемый результат:** Игрок удаляется **только** из этого списка. В логах `Удаление из очереди: <ник> удален из активной очереди.` (или `... из списка ожидающих.`). Удаление из истории невозможно — кнопка скрыта.

- [ ] **6.5.5. Кнопка «Бан»**
  - **Действие:** Нажмите `Бан` на карточке игрока.
  - **Ожидаемый результат:** Игрок удаляется из **всех** списков и добавляется в бан-лист. В логах `Бан-лист очереди: <ник> добавлен.` Кнопка `Бан` на карточке — с тултипом `Забанить`.

- [ ] **6.5.6. Drag-and-drop внутри списка**
  - **Действие:** Зажмите ручку `Зажмите, чтобы перетащить игрока` и перетащите игрока выше/ниже в том же списке.
  - **Ожидаемый результат:** Порядок меняется, во время перетаскивания показывается полупрозрачная копия карточки. В логах `Игрок <ник> перемещен внутри активной очереди на позицию N.`

- [ ] **6.5.7. Drag-and-drop между списками**
  - **Действие:** Перетащите игрока из активной очереди в список ожидающих (и обратно).
  - **Ожидаемый результат:** Игрок переносится, в логах `Игрок <ник> перенесен из активной очереди в список ожидающих на позицию N.`

- [ ] **6.5.8. Drag-and-drop при дубле в целевом списке**
  - **Действие:** Попробуйте перетащить игрока в список, где он уже есть (включая дубль по другому нику).
  - **Ожидаемый результат:** Перемещение отклоняется, в логах `Перемещение игрока: Отклонено, игрок <ник> уже находится в списке ожидающих.` Списки не меняются.

- [ ] **6.5.9. Клик по кнопкам не запускает перетаскивание**
  - **Действие:** Кликните по карточке игрока и слегка двиньте мышь (меньше 8 px).
  - **Ожидаемый результат:** Перетаскивание не начинается, срабатывает только клик по кнопке.

### 6.6. Модальное окно «Карта участника очереди»

- [ ] **6.6.1. Содержимое карточки**
  - **Действие:** Откройте `Подробно` для игрока.
  - **Ожидаемый результат:** Поля: `Twitch Login:` (отображаемый ник), `Игровой ник:` (ник либо `Игра не выбрана в настройках` / `Не определен`), `Добавлен в:` (дата и время в формате ru-RU). Чипы: `Источник:` (`Приложение` / `Команда модератора` / `Команда из чата`), `Модератор:` (`Да`/`Нет`), `VIP-статус:` (`Да`/`Нет`), `Подписчик:` (`Да`/`Нет`), `Текст сообщения:` (текст либо `Сообщение отсутствует`).

- [ ] **6.6.2. Кнопки модального окна**
  - **Действие:** Осмотрите кнопки внизу окна.
  - **Ожидаемый результат:** Есть `Забанить`, `Удалить`, `Удалить из всех очередей`, `Копировать ник`, `Закрыть`. Для игроков из истории кнопки `Удалить` и `Удалить из всех очередей` неактивны, кнопка `Копировать ник` неактивна, если игра не выбрана.

- [ ] **6.6.3. «Удалить из всех очередей»**
  - **Действие:** Нажмите `Удалить из всех очередей`.
  - **Ожидаемый результат:** Игрок удаляется из активной очереди и списка ожидающих. В логах запись с префиксом `Удаление из всех очередей`.

- [ ] **6.6.4. Закрытие модального окна**
  - **Действие:** Кликните по затемнённому фону вне окна или нажмите `Закрыть`.
  - **Ожидаемый результат:** Окно закрывается. После выполнения любой кнопки окно также закрывается.

### 6.7. Очистка списков

- [ ] **6.7.1. «Очистить текущую очередь»**
  - **Действие:** Настройки → секция `Очистить очередь` → `Очистить текущую очередь`.
  - **Ожидаемый результат:** Активная очередь пуста, в логах `Текущая очередь очищена.` Диалога подтверждения **нет**.

- [ ] **6.7.2. «Очистить список ожидающих»**
  - **Действие:** Нажмите `Очистить список ожидающих`.
  - **Ожидаемый результат:** Список ожидающих пуст, в логах `Список ожидающих очищен. Удалено N игроков.` (при непустом списке).

- [ ] **6.7.3. «Очистить историю»**
  - **Действие:** Нажмите `Очистить историю`.
  - **Ожидаемый результат:** История пуста, счётчик составов сброшен на `Состав №1`, **все кулдауны и лимиты игр сброшены**. В логах `История сыгранных сессий очищена.`

## 7. Настройки очереди

### 7.1. Раздел «Основные настройки»

- [ ] **7.1.1. «Лимит участников в очереди»**
  - **Действие:** Измените значение (по умолчанию 4, диапазон 1–99).
  - **Ожидаемый результат:** Значение применяется; бейдж активной очереди обновляется (`N / <новый лимит>`). При включённом автопереносе состав пересчитывается. Ввод фиксируется по `Enter` или при уходе фокуса; нечисловое значение откатывается; значение ограничивается диапазоном.

- [ ] **7.1.2. «Разрешить запись в список ожидающих»**
  - **Действие:** Включите чекбокс.
  - **Ожидаемый результат:** Секция `Список ожидающих` становится активной, список раскрывается. В логах `Настройки изменены: Разрешить запись в список ожидающих - Вкл`.

- [ ] **7.1.3. «Разрешить запись в список ожидающих участников текущей очереди»**
  - **Действие:** Попробуйте включить при выключенной предыдущей настройке.
  - **Ожидаемый результат:** Чекбокс неактивен (disabled). После включения списка ожидающих — активен: игрок из активной очереди может записаться и в список ожидающих.

- [ ] **7.1.4. «Разрешить автоперенос игроков из списка ожидающих при изменении размера очереди»**
  - **Действие:** Включите/выключите.
  - **Ожидаемый результат:** Управляет автоматическим переносом игроков между списками при изменении лимита, удалении и перемещении игроков. При выключенной предыдущей настройке — неактивен.

- [ ] **7.1.5. «Через сколько игр игрок может повторно участвовать»**
  - **Действие:** Установите, например, 2 (диапазон 0–99, 0 = выключено).
  - **Ожидаемый результат:** После того как игрок сыграл 2 сессии, его повторный вход отклоняется: `Добавление в очередь: Отклонено, игрок <ник> уже сыграл максимальное количество игр (<N>/<M>)` (в тексте подставляются фактические значения).

- [ ] **7.1.6. «Через сколько минут игрок может повторно участвовать»**
  - **Действие:** Установите, например, 30 (диапазон 0–1440, 0 = выключено).
  - **Ожидаемый результат:** Повторный вход игрока раньше срока отклоняется: `Добавление в очередь: Отклонено, кулдаун времени (осталось <N> мин.)`

- [ ] **7.1.7. «Лимит игр для одного игрока»**
  - **Действие:** Установите, например, 3 (диапазон 0–99, 0 = без лимита).
  - **Ожидаемый результат:** После 3 сыгранных игр вход отклоняется (см. 7.1.5). Счётчик обнуляется при очистке истории.

- [ ] **7.1.8. «Приоритет для подписчиков»**
  - **Действие:** Включите, затем вступите в очередь зрителем без подписки и подписчиком.
  - **Ожидаемый результат:** Подписчик/VIP/модератор вставляется перед первым не-подписчиком в списке.

- [ ] **7.1.9. «Вход только для подписчиков»**
  - **Действие:** Включите.
  - **Ожидаемый результат:** Зритель без подписки получает отказ `Добавление в очередь: Отклонено, доступ к очереди только для подписчиков Twitch, VIP и модераторов`. Подписчики, VIP и модераторы проходят. Чекбокс `Приоритет для подписчиков` при этом неактивен.

### 7.2. Раздел «Команды чата»

- [ ] **7.2.1. Список команд и их значения по умолчанию**
  - **Действие:** Откройте секцию `Команды чата`.
  - **Ожидаемый результат:** 9 команд с подписями: `Вступление в очередь` (`!join`), `Выход из очереди` (`!leave`), `Показать текущую очередь` (`!show`), `Очистить очереди` (`!clear`), `Добавить в очередь` (`!add`), `Удалить из очереди` (`!delete`), `Открыть очередь` (`!start`), `Закрыть очередь` (`!stop`), `Завершить текущую очередь` (`!play`).

- [ ] **7.2.2. Изменение имени команды**
  - **Действие:** Замените `!join` на `!вход` (или `!play`).
  - **Ожидаемый результат:** Новая команда работает, старая — нет. В логах `Настройки изменены: Триггер команды "Вступление в очередь" изменен с "!join" на "!вход"`.

- [ ] **7.2.3. Фиксация и отмена ввода**
  - **Действие:** Измените команду и нажмите `Escape`; затем нажмите `Enter`.
  - **Ожидаемый результат:** `Escape` возвращает прежнее значение, `Enter` сохраняет новое и убирает фокус.

- [ ] **7.2.4. Чекбокс «Мод»**
  - **Действие:** Включите его у команды `!show`.
  - **Ожидаемый результат:** Команда становится доступной только модераторам и стримеру. В логах `Настройки изменены: Доступ к команде "!show" (Показать текущую очередь) только для модераторов - "Вкл"`. Подсказка чекбокса: `Только для модераторов`.

### 7.3. Раздел «Разрешения боту на отправку сообщений»

- [ ] **7.3.1. Главный переключатель**
  - **Действие:** Включите `Разрешить боту отправку сообщений в чат` (по умолчанию выключено).
  - **Ожидаемый результат:** Все остальные переключатели секции становятся активными. При выключении — блокируются, и бот не отправляет ничего.

- [ ] **7.3.2. Префикс сообщений**
  - **Действие:** Измените `Префикс для автоматических сообщений в чат Twitch` (по умолчанию `🎮 [PartyBot]`, максимум 20 символов).
  - **Ожидаемый результат:** Новый префикс используется во всех автоматических сообщениях. Лишние символы сверх 20 обрезаются, значение подрезается от пробелов.

- [ ] **7.3.3. Мгновенные сообщения**
  - **Действие:** Включите/выключите `Сообщение об открытии очереди (мгновенное)`, `Сообщение об заполнении текущей очереди (мгновенное)`, `Сообщение о закрытии очереди (мгновенное)`, `Сообщение об очистке активного состава игроков (мгновенное)`, `Сообщение об очистке списка ожидающих (мгновенное)`.
  - **Ожидаемый результат:** Каждое событие отправляет (или не отправляет) соответствующее сообщение в чат. Сообщения приходят без задержки.

- [ ] **7.3.4. Отложенные сообщения**
  - **Действие:** Включите `Сообщение о добавлении игрока в очередь (с задержкой)`, `Сообщение о удалении игрока из очереди (с задержкой)`, `Сообщение о перемещении игрока между очередями (с задержкой)`.
  - **Ожидаемый результат:** Сообщения приходят пачками с интервалом `Задержка ответов бота об изменениях в составе очереди (сек)` (по умолчанию 5 с, диапазон 1–99).

### 7.4. Раздел «Валидация никнеймов для игры»

- [ ] **7.4.1. Выбор игры**
  - **Действие:** Откройте выпадающий список (первый пункт — `—`).
  - **Ожидаемый результат:** Доступны 10 игр: `Riot Games`, `Steam`, `Ubisoft Connect`, `Battle.net`, `Apex Legends`, `PUBG: Battlegrounds`, `Fortnite`, `Naraka: Bladepoint`, `Goose Goose Duck`, `Among Us`. Под списком появляется строка `Активный паттерн:` с регулярным выражением в блоке кода. В логах `Настройки изменены: Выбрана игра - <КЛЮЧ>`.

- [ ] **7.4.2. Снятие выбора игры**
  - **Действие:** Выберите `—`.
  - **Ожидаемый результат:** Паттерн не отображается (или отображается ` не выбрано`), извлечение игровых ников отключается, в модальном окне игрока поле `Игровой ник:` показывает `Игра не выбрана в настройках`, кнопка `Копировать ник` неактивна.

- [ ] **7.4.3. Валидация по играм**
  - **Действие:** Для каждой игры вступите в очередь с разными вариантами ника (см. таблицу в разделе 10) и проверьте наличие зелёного чипа с игровым ником.

- [ ] **7.4.4. Извлечение ника из сообщения**
  - **Действие:** Напишите в чат `!join Player#123` при выбранной игре `Riot Games`.
  - **Ожидаемый результат:** В карточке игрока виден чип с ником `Player#123` (команда `!` в начале сообщения игнорируется при разборе).

### 7.5. Раздел «Банлист очереди»

- [ ] **7.5.1. Добавление ника в бан-лист**
  - **Действие:** Введите ник в поле `Добавить никнейм на Twitch...` и нажмите кнопку добавления (или `Enter`).
  - **Ожидаемый результат:** Ник появляется в списке. В логах `Бан-лист очереди: <ник> добавлен.`

- [ ] **7.5.2. Повторное добавление**
  - **Действие:** Добавьте тот же ник повторно.
  - **Ожидаемый результат:** `Бан-лист очереди: <ник> уже находится в бан-листе.` Дубликат не создаётся.

- [ ] **7.5.3. Удаление из бан-листа**
  - **Действие:** Нажмите кнопку с иконкой корзины у записи (тултип `Удалить из списка`).
  - **Ожидаемый результат:** Запись удаляется, в логах `Бан-лист очереди: <ник> удален из бан-листа очереди.`

- [ ] **7.5.4. Эффект бана**
  - **Действие:** Добавьте ник в бан-лист, затем попросите этого зрителя написать `!join`.
  - **Ожидаемый результат:** Отказ `Добавление в очередь: Отклонено, игрок находится в бан-листе очереди`. Сравнение регистронезависимое.

- [ ] **7.5.5. Неактивная кнопка добавления**
  - **Действие:** Оставьте поле пустым.
  - **Ожидаемый результат:** Кнопка добавления неактивна.

### 7.6. Раздел «Восстановить настройки по умолчанию»

- [ ] **7.6.1. Сброс настроек**
  - **Действие:** Измените несколько настроек, затем нажмите `Восстановить настройки`.
  - **Ожидаемый результат:** Все настройки вернутся к значениям по умолчанию (лимит 4, список ожидающих выключен, автоперенос включён, кулдауны 0, префикс `🎮 [PartyBot]`, отправка сообщений выключена, команды по умолчанию), бан-лист очищается, игра не выбрана. Подтверждения в виде диалога **нет**.

### 7.7. Журнал изменений настроек

- [ ] **7.7.1. Лог изменения значения**
  - **Действие:** Измените любое число/текстовое поле.
  - **Ожидаемый результат:** В панели `Логи` появляется запись вида `Настройки изменены: <название настройки> - <значение>`.

- [ ] **7.7.2. Лог изменения переключателя**
  - **Действие:** Включите/выключите чекбокс.
  - **Ожидаемый результат:** Запись `Настройки изменены: <название> - Вкл` или `... - Выкл`.

- [ ] **7.7.3. Лог изменения разрешений на сообщения**
  - **Действие:** Измените переключатель в секции разрешений.
  - **Ожидаемый результат:** Запись с префиксом `Настройки изменены (Сообщения): <название> - Вкл/Выкл`.

## 8. Команды чата

> Команды обрабатываются, пока панель `Очередь` не свёрнута полностью (обработчик подключён внутри неё). Команда должна начинаться с `!`, регистр команды чувствителен.

- [ ] **8.1. `!join` — вступление в очередь**
  - **Действие:** Зритель пишет `!join` в чате Twitch.
  - **Ожидаемый результат:** Зритель попадает в активную очередь. В логах `Добавление в очередь: Игрок <ник> добавлен в активную очередь.` (источник — `Участник чата`).

- [ ] **8.1.1. `!join` при закрытой очереди**
  - **Ожидаемый результат:** Отказ `Добавление в очередь: Отклонено, очередь закрыта`.

- [ ] **8.1.2. `!join` при заполненной очереди без списка ожидающих**
  - **Ожидаемый результат:** Отказ `Добавление в очередь: Отклонено, активная очередь заполнена, а список ожидающих отключен.`

- [ ] **8.1.3. `!join` при заполненной очереди со списком ожидающих**
  - **Ожидаемый результат:** Игрок попадает в список ожидающих, в логах `Добавление в очередь: Игрок <ник> добавлен в список ожидания.`

- [ ] **8.1.4. Повторный `!join`**
  - **Ожидаемый результат:** Отказ `Добавление в очередь: Отклонено, игрок <ник> уже в активной очереди, список ожидающих отключен.` (либо `... уже находится в активной очереди, повторная запись запрещена.` при включённой повторной записи).

- [ ] **8.2. `!leave` — выход из очереди**
  - **Действие:** Зритель пишет `!leave`.
  - **Ожидаемый результат:** Игрок удаляется из активной очереди **и** списка ожидающих. В логах запись с префиксом `Удаление из очереди` / `Удаление из всех очередей`.

- [ ] **8.3. `!show` — показать очередь**
  - **Действие:** Напишите `!show` в чате.
  - **Ожидаемый результат:** Бот отвечает в чат сообщением вида `🎮 [PartyBot] (2/4) В очереди: @a, @b | В ожидании: @c`. Если списки пусты — `(0/4) Пуста.`

- [ ] **8.4. `!clear` — очистить очереди (только для модераторов)**
  - **Действие:** Модератор пишет `!clear`.
  - **Ожидаемый результат:** Активная очередь и список ожидающих очищены, бот отвечает `Текущая очередь и список ожидания очищены.` (без префикса).

- [ ] **8.5. `!add <ник>` — добавить игрока (только для модераторов)**
  - **Действие:** Модератор пишет `!add @player1`.
  - **Ожидаемый результат:** Игрок добавлен в очередь, источник — `Команда модератора`. Ведущий `@` допускается, ник приводится к нижнему регистру.

- [ ] **8.6. `!delete <ник>` — удалить игрока (только для модераторов)**
  - **Действие:** Модератор пишет `!delete @player1`.
  - **Ожидаемый результат:** Игрок удаляется из всех списков очереди.

- [ ] **8.7. `!start` / `!stop` — открыть/закрыть очередь (только для модераторов)**
  - **Ожидаемый результат:** Очередь открывается/закрывается, состояние кнопок в приложении синхронизируется.

- [ ] **8.8. `!play` — завершить очередь (только для модераторов)**
  - **Ожидаемый результат:** Состав переносится в историю, бот пишет `🎮 [PartyBot] Очередь завершена. Сейчас играют: @a, @b`.

- [ ] **8.9. Команды от обычного зрителя**
  - **Действие:** Зритель (не модератор) пишет `!clear`, `!add`, `!delete`, `!start`, `!stop`, `!play`.
  - **Ожидаемый результат:** Команды **молча игнорируются** — нет ни сообщения в чат, ни записи в логах.

- [ ] **8.10. Команда без аргумента**
  - **Действие:** Модератор пишет `!add` или `!delete` без ника.
  - **Ожидаемый результат:** Команда игнорируется, ничего не происходит.

- [ ] **8.11. Переопределение команд**
  - **Действие:** Переименуйте `!join` в `!q` в настройках и напишите в чат `!q` и `!join`.
  - **Ожидаемый результат:** Работает только `!q`; `!join` игнорируется.

- [ ] **8.12. Команды при свёрнутой панели «Очередь»**
  - **Действие:** Полностью сверните панель `Очередь` и напишите в чат `!join`.
  - **Ожидаемый результат:** Команда **не обрабатывается** (обработчик находится внутри свёрнутой панели). Это текущее поведение приложения — зафиксировать как известное ограничение.

- [ ] **8.13. Команда не от самого себя**
  - **Действие:** Отправьте через приложение обычное сообщение (не начинающееся с `!`).
  - **Ожидаемый результат:** Свои не-командные сообщения не обрабатываются как команды.

## 9. Уведомления бота в чате

> Требуется включённая настройка `Разрешить боту отправку сообщений в чат`.

- [ ] **9.1. Сообщение об открытии очереди**
  - **Действие:** Откройте очередь.
  - **Ожидаемый результат:** `🎮 [PartyBot] Очередь открыта! Доступные команды: !join для входа, !leave для выхода, !show для просмотра очереди.` (по умолчанию перечислены только команды, доступные всем).

- [ ] **9.2. Сообщение об закрытии очереди**
  - **Ожидаемый результат:** `🎮 [PartyBot] Очередь закрыта! | (2/4) В очереди: @a, @b` — состав очереди выводится после вертикальной черты.

- [ ] **9.3. Сообщение о заполнении очереди**
  - **Действие:** Заполните очередь до лимита.
  - **Ожидаемый результат:** `🎮 [PartyBot] Очередь заполнена. Текущий состав: (4/4) В очереди: @a, @b, @c, @d`. Сообщение отправляется один раз — при переходе в состояние «заполнено», не при каждом добавлении.

- [ ] **9.4. Сообщения об очистке**
  - **Ожидаемый результат:** `🎮 [PartyBot] Очередь очищена.` и `🎮 [PartyBot] Список ожидающих очищен.`

- [ ] **9.5. Пакетное сообщение об изменениях состава**
  - **Действие:** Добавьте, удалите и переместите игроков за один интервал.
  - **Ожидаемый результат:** Через N секунд (по умолчанию 5) приходит одно сообщение вида `🎮 [PartyBot] Добавлены: 🟢@a, 🟢@b | Удалены: 🔴@c | Перемещены в очередь: 🟢@d | Перемещены в ожидающие: 🟡@e`. Группы: `Добавлены:`, `Добавлены в ожидающие:`, `Удалены:`, `Перемещены в очередь:`, `Перемещены в ожидающие:`, `Отказано:`. Разделитель групп — ` | `.

- [ ] **9.6. Обрезка длинных сообщений**
  - **Действие:** Добавьте много игроков, чтобы текст сообщения превысил 400 символов.
  - **Ожидаемый результат:** Сообщение укорачивается до безопасного лимита 400 символов, лишние игроки убираются (в конце группы появляется ` +N`).

- [ ] **9.7. Главный переключатель отправки**
  - **Действие:** Выключите `Разрешить боту отправку сообщений в чат` и выполните действие (открытие очереди, `!join`, `!show`).
  - **Ожидаемый результат:** Бот **не** отправляет никаких сообщений в чат.

- [ ] **9.8. Поведение при недоступном чате**
  - **Действие:** Включите уведомления, отключите сеть, вызовите событие очереди, затем восстановите сеть.
  - **Ожидаемый результат:** События накапливаются и отправляются после восстановления связи. В логах при ошибке: `Не удалось отправить сообщение в чат: <текст>. Причина: <причина>`.

- [ ] **9.9. Уведомление о бане аккаунта**
  - **Действие:** Забаните аккаунт бота на канале и вызовите событие очереди.
  - **Ожидаемый результат:** В логах предупреждение `Отправка уведомлений приостановлена: аккаунт забанен. Накопленные события будут отправлены после восстановления доступа.` Статус чата в шапке — `Забанен`.

- [ ] **9.10. Лог успешной отправки**
  - **Ожидаемый результат:** В логах `Автоматически отправлено сообщение в чат: <текст>` (зелёный статус).

## 10. Валидация игровых никнеймов

| Игра | Паттерн | Пример валидного ника | Пример невалидного |
| --- | --- | --- | --- |
| Riot Games | `^.{3,16}#[a-zA-Z0-9]{3,5}$` | `Player#123` | `Pl#1`, `Player#123456` |
| Steam | `^.{2,32}$` | `my_nick` | `x` (1 символ) |
| Ubisoft Connect | `^[a-zA-Z0-9._-]{3,15}$` | `my.nick_01` | `ab` (2 символа), `my nick` |
| Battle.net | `^(?![0-9]).{3,12}#[0-9]+$` | `Player#1234` | `1Player#1`, `Player#` |
| Apex Legends | `^[a-zA-Z0-9_-]{4,16}$` | `player_01` | `abc` (3 символа) |
| PUBG: Battlegrounds | `^[a-zA-Z0-9]{4,16}$` | `player01` | `player_01` (подчёркивание) |
| Fortnite | `^[a-zA-Z0-9а-яА-ЯёЁ_\s-]{3,16}$` | `Игрок_1` | `ab` |
| Naraka: Bladepoint | `^.{1,14}$` | `abc` | 15+ символов |
| Goose Goose Duck | `^[a-zA-Z0-9а-яА-ЯёЁ]{1,16}$` | `Играющий` | `my nick` (пробел) |
| Among Us | `^.{1,10}$` | `crew` | 11+ символов |

- [ ] **10.1. Валидный ник**
  - **Действие:** Выберите игру и вступите в очередь с подходящим ником.
  - **Ожидаемый результат:** В карточке игрока появляется зелёный чип с игровым ником; в модальном окне поле `Игровой ник:` заполнено.

- [ ] **10.2. Невалидный ник**
  - **Действие:** Вступите в очередь с неподходящим ником.
  - **Ожидаемый результат:** Игровой ник не извлекается — в модальном окне `Игровой ник: Не определен`.

- [ ] **10.3. Разбор по словам**
  - **Действие:** Напишите `!join МойНик` — ник содержит только одно слово.
  - **Ожидаемый результат:** Ник извлекается из первого подходящего слова сообщения. Ник с пробелом (из нескольких слов) не распознаётся.

- [ ] **10.4. Ложные срабатывания**
  - **Действие:** При выбранной игре `Steam` (паттерн `^.{2,32}$`) напишите `!join hello`.
  - **Ожидаемый результат:** Слово `hello` будет распознано как игровой ник (текущее поведение регулярных выражений — зафиксировать как известное ограничение).

## 11. Панель логов

- [ ] **11.1. Отображение записей**
  - **Действие:** Выполните несколько действий (открытие очереди, добавление игрока, изменение настройки) и откройте панель `Логи`.
  - **Ожидаемый результат:** Каждая запись содержит: время `[ЧЧ:ММ:СС]`, иконку источника, имя актора и текст сообщения. Между записями — тонкий разделитель.

- [ ] **11.2. Иконки источников**
  - **Действие:** Посмотрите на иконки разных записей (при наведении — тултип).
  - **Ожидаемый результат:** `Пользователь приложения` (корона), `Модератор в чате` (щит), `Участник чата` (облачко сообщения), `Система` (процессор).

- [ ] **11.3. Цвета статусов**
  - **Ожидаемый результат:** Обычная запись — нейтральный цвет, успех — зелёный, предупреждение — жёлтое/оранжевое, ошибка — красное.

- [ ] **11.4. Порядок сообщений**
  - **Ожидаемый результат:** Новые записи появляются **снизу** (как в чате), старые — сверху.

- [ ] **11.5. Ёмкость логов**
  - **Действие:** Сгенерируйте более 1000 записей.
  - **Ожидаемый результат:** Хранятся только последние 1000 записей, более старые удаляются.

- [ ] **11.6. Сохранение логов**
  - **Действие:** Перезагрузите страницу.
  - **Ожидаемый результат:** Логи **не** сохраняются — панель пустая (логи живут только в памяти вкладки).

## 12. Интерфейс, темы и адаптивность

### 12.1. Панели

- [ ] **12.1.1. Сворачивание и разворачивание**
  - **Действие:** Нажмите кнопку-стрелку в заголовке любой панели.
  - **Ожидаемый результат:** Панель сворачивается в узкую полосу (48 px) с вертикально ориентированным заголовком, либо в полосу 48 px по высоте. Тултип: `Скрыть <название>` / `Открыть <название>`. Анимация плавная (≈300 мс).

- [ ] **12.1.2. Сохранение состояния панелей**
  - **Действие:** Сверните панель и перезагрузите страницу.
  - **Ожидаемый результат:** Состояние панели сохраняется (ключи `panel_*_open` в `localStorage`).

- [ ] **12.1.3. Взаимное переключение панелей**
  - **Действие:** На разных размерах окна откройте/закройте панели `Настройки`, `Очередь`, `Логи`, `Чат трансляции`.
  - **Ожидаемый результат:** На `md`/`lg`: `Настройки` и `Очередь` образуют пару, `Логи` и `Чат трансляции` — вторую. На `xl`: `Настройки` ↔ `Логи`, а `Очередь` и `Чат` независимы. На `2xl`: все четыре независимы. Зафиксировать фактическое поведение.

- [ ] **12.1.4. Свернуть панель «Чат трансляции»**
  - **Ожидаемый результат:** Тултип кнопки — `Скрыть чат трансляции` / `Открыть чат трансляции`.

### 12.2. Адаптивность

- [ ] **12.2.1. Мобильная ширина (< 768 px)**
  - **Действие:** Сузьте окно до 375–430 px.
  - **Ожидаемый результат:** Панели выстроены в одну колонку, вертикальные. При открытии одной панели остальные закрываются. Панели `Очередь` и `Чат трансляции` недоступны одновременно.

- [ ] **12.2.2. Планшетная ширина (768–1279 px)**
  - **Ожидаемый результат:** Две колонки: слева `Настройки` + `Очередь`, справа `Логи` + `Чат трансляции`.

- [ ] **12.2.3. Десктоп (1280–1535 px)**
  - **Ожидаемый результат:** Слева `Настройки` + `Логи`, справа `Очередь` + `Чат трансляции` (бок о бок, горизонтальные панели).

- [ ] **12.2.4. Широкий экран (≥ 1536 px)**
  - **Ожидаемый результат:** Все четыре панели в один ряд, все горизонтальные.

- [ ] **12.2.5. Смена размера окна**
  - **Действие:** Измените ширину окна «на лету».
  - **Ожидаемый результат:** Раскладка перестраивается, открытые панели выбираются автоматически согласно правилам для нового брейкпоинта.

### 12.3. Темы

- [ ] **12.3.1. Переключение темы**
  - **Действие:** Нажмите на переключатель темы в шапке (или строку `тема оформления:` в меню профиля).
  - **Ожидаемый результат:** Тема циклически переключается: `Светлая` (nord) → `Темная` (dim) → `Системная` (system) → `Светлая`. Бейдж показывает описание текущей темы.

- [ ] **12.3.2. Системная тема**
  - **Действие:** Выберите `Системная` и измените тему ОС (светлая/тёмная).
  - **Ожидаемый результат:** Приложение переключается вслед за системной темой без перезагрузки.

- [ ] **12.3.3. Сохранение темы**
  - **Действие:** Выберите тему и перезагрузите страницу.
  - **Ожидаемый результат:** Тема сохраняется в `localStorage` (`twitch_party_theme`) и восстанавливается.

- [ ] **12.3.4. Некорректное значение темы**
  - **Действие:** Запишите в `twitch_party_theme` произвольную строку и перезагрузите страницу.
  - **Ожидаемый результат:** Приложение откатывается к теме `Системная` и перезаписывает значение в хранилище.

- [ ] **12.3.5. Синхронизация темы между вкладками**
  - **Действие:** Смените тему в одной вкладке, посмотрите на другую.
  - **Ожидаемый результат:** Тема меняется во второй вкладке автоматически.

## 13. Синхронизация и хранение данных

- [ ] **13.1. Синхронизация очереди между вкладками**
  - **Действие:** Откройте две вкладки приложения, в первой добавьте игрока.
  - **Ожидаемый результат:** Во второй вкладке игрок появляется в очереди без перезагрузки.

- [ ] **13.2. Синхронизация настроек между вкладками**
  - **Действие:** Во вкладке 1 измените лимит очереди, во вкладке 2 смените тему.
  - **Ожидаемый результат:** Обе вкладки обновляются мгновенно.

- [ ] **13.3. Синхронизация канала**
  - **Действие:** Смените канал в одной вкладке.
  - **Ожидаемый результат:** Вторая вкладка переключается на тот же канал (значение `tqp_active_channel` общее).

- [ ] **13.4. Независимость сессий**
  - **Действие:** Выйдите из аккаунта в одной вкладке.
  - **Ожидаемый результат:** Вторая вкладка **остаётся** авторизованной (сессия хранится в `sessionStorage` и не синхронизируется).

- [ ] **13.5. Сохранение очереди при перезагрузке**
  - **Действие:** Добавьте игроков, обновите страницу.
  - **Ожидаемый результат:** Состав очереди, список ожидающих, история и настройки сохраняются.

- [ ] **13.6. Очистка данных браузера**
  - **Действие:** Очистите данные сайта и откройте приложение заново.
  - **Ожидаемый результат:** Приложение полностью сброшено: экран приветствия, пустые очередь и настройки, тема по умолчанию.

- [ ] **13.7. Ограничение размера хранилища**
  - **Действие:** Искусственно запишите в `twitch_queue_data` больше 100 сессий истории и больше 100 записей кулдаунов, затем откройте приложение.
  - **Ожидаемый результат:** Приложение автоматически подрезает данные до лимитов (100 сессий / 100 игроков).

## 14. Известные ограничения и потенциальные дефекты

> Проверьте каждый пункт и зафиксируйте, подтверждается ли поведение.

- [ ] **14.1. Нет подтверждения деструктивных действий**
  - **Действие:** Нажмите `Очистить текущую очередь`, `Очистить историю`, `Восстановить настройки`, `Забанить`.
  - **Ожидаемый результат:** Действие выполняется мгновенно, без диалога подтверждения. (Риск случайной потери данных.)

- [ ] **14.2. Команды чата не работают при свёрнутой панели «Очередь»**
  - **Действие:** Сверните панель `Очередь` полностью и напишите `!join`.
  - **Ожидаемый результат:** Команда не обрабатывается.

- [ ] **14.3. Нет кнопки очистки логов**
  - **Ожидаемый результат:** Функция `clearLogs` существует в контексте, но кнопка в UI отсутствует.

- [ ] **14.4. Разные форматы времени в чате и логах**
  - **Действие:** Сравните время сообщения в чате и время записи в логах.
  - **Ожидаемый результат:** В чате — `ЧЧ:ММ:СС` (ru-RU), в логах — время в локали браузера. Визуальное расхождение.

- [ ] **14.5. Нет поддержки эмоций Twitch**
  - **Ожидаемый результат:** Эмоции отображаются как обычный текст. Отдельного парсинга тега `emotes` нет.

- [ ] **14.6. Автозакрытие очереди при смене канала срабатывает и при монтировании**
  - **Действие:** Оставьте очередь открытой в `localStorage`, затем перезагрузите страницу.
  - **Ожидаемый результат:** Очередь закрывается с записью `Очередь автоматически закрыта в связи с переключением на канала.` — даже если канал не менялся.

- [ ] **14.7. Лимит ввода чата (500) больше безопасного лимита ботовых сообщений (400)**
  - **Ожидаемый результат:** Длинные автоматические сообщения молча укорачиваются до 400 символов.

- [ ] **14.8. Грамматическая особенность в тексте лога**
  - **Ожидаемый результат:** Строка `Очередь автоматически закрыта в связи с переключением на канала.` содержит неточность — исправить при следующем релизе.

- [ ] **14.9. Сообщение «Имя канала не может быть пустым.» недостижимо из UI**
  - **Ожидаемый результат:** Кнопка подключения неактивна при пустом поле, поэтому ошибка пользователю не показывается.

- [ ] **14.10. `!clear` не использует префикс бота**
  - **Действие:** Выполните `!clear` от модератора.
  - **Ожидаемый результат:** Сообщение `Текущая очередь и список ожидания очищены.` отправляется **без** префикса `🎮 [PartyBot]`, в отличие от остальных сообщений.

- [ ] **14.11. `!add` не наследует роли пользователя**
  - **Ожидаемый результат:** Игрок, добавленный командой `!add`, создаётся без признаков модератора/подписчика/VIP.

- [ ] **14.12. Нет счётчиков зрителей/подписчиков/фолловеров в карточке канала**
  - **Ожидаемый результат:** Карточка `Текущий канал` показывает только роли и ограничения чата. Числовые показатели канала не выводятся.

- [ ] **14.13. Классы `animate-fadeIn` и `custom-scrollbar` не определены в CSS**
  - **Ожидаемый результат:** Анимация появления сообщений и кастомный скроллбар фактически не работают.
